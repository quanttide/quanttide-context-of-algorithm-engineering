# 内容归属分类

## 目的

为算法训练找一个可验证、可讲解的实际案例。

## 判据

标签必须是**事实**，不是**观测结果**。

预测「某件事会不会发生」只有统计相关性，没有标准答案可以对——比如预测一个 PR 会不会被合并，没有人能指着某一条说「这题的标准答案是 X」。而「这篇文档该放在哪一层」是已有的事实，可以逐条核对，判据也写在文档规范里，人能讲清。

## 数据

取自仓库族各领域第二大脑的 `data/<层>/` 目录，共 1210 篇文档。标签是它实际所在的层。

- 档案 profile：388
- 日志 journal：271
- 语境 context：159
- 洞察 insight：140
- 意图 intention：85
- 报告 report：77
- 路线图 roadmap：60
- 宣传册 brochure：30

## 做法

按 5 折交叉验证：TF-IDF 抽词，逻辑回归分类，与「全猜最多的一类」作基线比较。

三档难度：

- 第 1 步 日志与洞察两分类：411 篇，基线 0.659，模型 0.898
- 第 2 步 内容流向四层（日志、洞察、意图、路线图）：556 篇，基线 0.487，模型 0.793
- 第 3 步 八层全量：1210 篇，基线 0.321，模型 0.656

## 结果

三档都明显高于基线，且错误集中可解释：八层那一档的混淆几乎全在对角线上，唯一成规模的是日志与档案之间（9 例）、语境与日志之间（4 例）。

这不是模型的问题——档案本来就由日志提炼而来，语境本来就以日志体写成，它们同源。

另有一点值得留意：标签会漂移。文档会在层之间搬家（草稿定稿后归位），所以「标签是事实」里的那个事实会变，这是活的知识库的固有性质。

## 排除的候选

- 预测 PR 合并：只有统计相关性，没有标准答案可对
- 记忆类型四分类（情景、语义、自我、程序）：准确率 0.265，低于基线 0.302——标签是作者的写作意图，文本里没有信号
- 提交类型分类（feat、fix、docs 等）：chore 占 78.5%，严重失衡，容易教出「全猜多数类」的坏直觉

## 结论

内容归属分类适合作为算法训练的第一个实际案例：标签是事实、判据是明文规则、数据现成 1210 篇、三档难度已量出、错误可自行解释。

可复现脚本见同目录 `layer_classification.py`。
